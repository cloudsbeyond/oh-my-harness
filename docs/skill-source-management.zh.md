# Skill 资产管理与宿主接入

[English](skill-source-management.md) · [架构](architecture.md) · [命令与实际目录](../extensions/skill-source-management/README.md#commands-and-state)

## 目标与支持范围

管理器将一份经过审查、可追踪版本的 Skill 源接入各宿主的发现机制，避免多份可编辑副本漂移。Skill 触发、工具和权限仍由消费它的 harness 掌握；管理器独立于模型和能力请求运行。

当前管理**独立 Skill**，提供 Codex 和 Claude Code 发现适配。Python 3.11+ 检查可跨平台，生命周期写入依赖 macOS。支持本地候选；远程获取、完整插件/缓存管理、托管分发均后置，不自动接管已有管理器、注册表或原生策略。

## 为什么区分源身份与宿主发现

把 Skill 复制到每个客户端，可以解决初次可用，却形成多份独立源码。只更新一份会让行为漂移，按名称统一覆盖又可能丢失本地修改，或混淆许可与版本。保留完整的已接受发布单元、来源和摘要，才能明确实际使用哪份源，而不是仅凭版本号判断兼容性。

发布和发现是不同操作，但不一定发生在不同时间：宿主可能在写入绑定记录之前就已扫描正式源。因此，解绑管理记录不能普遍等同于禁用 Skill。发现适配必须保留宿主的真实规则，工具权限与执行决策仍由宿主负责。

更新也不只是替换一个目录。字节已经改变后，注册表或接入记录仍可能更新失败。已审查摘要、保留的旧内容与阶段收据，使部分完成的状态可以核对；受保护回滚则防止旧操作覆盖后续工作。这些机制支持可恢复的资产管理，但不构成对同一用户任意进程的隔离。

## 设计不变量

- **完整发布单元：** 审查完整 Skill、资源和许可，不通过拆分不兼容插件来绕过范围限制。
- **身份明确：** 分别保留来源/ref、声明版本、许可证据和已接受摘要。摘要覆盖路径、权限位、字节和相对链接，用于检测漂移，不能证明可信或授权执行。
- **源与状态分离：** 正式资产位于本 checkout 外；候选和操作收据位于发现目录与源 Git 外。私有 Skill 保留自己的许可和可见性。
- **受保护的变更：** 发布检查已审查候选摘要，更新还检查预期当前摘要。保留旧内容，拒绝覆盖外部目标、后续编辑或已变化的备份。
- **明确发现归属：** 只接入支持的入口或记录。宿主可能在 bind 前直接扫描正式源；默认 Codex 发现不会因解绑记录而停止。
- **可恢复的生命周期：** 包替换、注册表和客户端入口不是单一原子事务，中断后先核对收据再重试。管理器锁不隔离同 UID 的任意其它程序。

命令、实际目录、各客户端解绑方式和恢复步骤统一由[模块 README](../extensions/skill-source-management/README.zh.md)维护。

## 验收与实现顺序

分别验证各个边界：

| 边界 | 必需证据 |
| --- | --- |
| 源 | 身份、内容与许可已审查，不混入运行时或凭据 |
| 生命周期 | 在临时 Home 中验证更新、漂移拒绝、回滚和中断处理 |
| 发现 | 新客户端进程加载正确的已接受内容，撤回行为符合预期 |
| 执行 | 另行授权的代表性使用；共享文件不保证相同模型行为或权限 |

[验证命令与原生客户端夹具](../extensions/skill-source-management/README.zh.md#验证)分别记录发现/正文注入与业务执行。

## 扩展准入

先验证目标宿主的真实发现契约，再新增适配器。复用其支持的 loader 和生命周期，保留来源及受管入口撤回边界，使用临时状态测试。新增客户端或平台需要独立证据；接受资产不能推导 Hook、凭据或权限变更授权。[共同扩展流程](providers.md#extension-workflow)
