# 多 Agent 共享 Skill 源管理

[English](skill-source-management.md) · [项目架构](architecture.md)

**状态：初版可选模块已实现，本文也保留更广的设计范围。** [本地 CLI 模块](../extensions/skill-source-management/README.zh.md)支持 macOS 上独立 Skill 的审查发布和 Codex、Claude Code 接入。完整插件、TRAE、远程获取、原生开关和 Hook 管理仍未实现。不新增模型、MCP 接口或配置。

## 工作目标与项目定位

让多个本机 Agent 复用第三方与个人 Skill，避免每个客户端维护独立实体、按名称猜版本、反复实现安装和同步逻辑。验收目标是：每个完整发布单元只有一份已接受的可编辑源，版本证据明确，各客户端入口能够分别验证。相同文件并不保证不同 Agent 的触发和执行效果相同。

这与 oh-my-harness 的 provider-neutral 能力执行核心互补。能力核心已有 MCP 和原生 DSH 入口，Skill 源管理不进入其调用链路：

| 事项 | 归属 |
| --- | --- |
| 模型推理与供应方鉴权 | Model Proxy 或既有模型服务 |
| 调用供应方、独立 harness 的可执行工具 | 能力执行核心及 MCP、原生宿主适配器 |
| 发布可被本机 Agent 发现的 Skill 指令和资源 | 本方案提出的可选客户端源管理器 |
| 何时触发 Skill、能使用哪些工具、如何执行 | 消费它的 Agent 或 harness |

Skill 是指令与资源包，不等于一个可执行 MCP 工具。不能把每个 Skill 都改造成 provider capability、每次请求注入全部正文，或让模型代理依赖 Skill 安装。这份设计在现有请求路径之外，因此[运行时架构图](architecture.json)不增加已实现组件。

开源仓库保存可复用方案和可选管理器代码，不作为用户的集中安装目录。实际接受的技能放在用户控制的源目录。管理器开源，不意味着个人或内部 Skill 必须公开。

## 范围与非目标

P0 管理用户级第三方、个人 Skill，以及可以通过适配共享的完整发布包。项目专用 Skill 默认留在项目中，不强行全局化。

内置技能、公司托管 Hook、账号、凭证、模型配置、MCP 连接和运行时权限保留原有归属。有脚本不等于与某个 Agent 耦合，要核对真实 API、路径、工具与调用依赖；反过来，正文相同也不证明两个完整插件可以互换。

不再用 `.variants` 或客户端后缀目录维护多套正式源。不能为了目录整齐而强行统一不兼容版本。尚未解决的原件与备份保留在发现范围之外，等待明确决策。

## 正式源与运行状态分开

参考方案把 `~/.agents/skills` 作为正式源根目录。初版模块已允许显式指定 Home、源根和状态根，不硬编码个人主目录。

```text
~/.agents/
  skills/                         已接受、可编辑的正式源
    .git/                         源版本历史，不是操作记录
    .source-registry.json         来源身份和受管公开入口
    shared-review/
      SKILL.md
      scripts/
      references/
      assets/
    workflow-suite/                一个完整发布单元
      .plugin-source.json
      .source/                    已接受的包快照，不是 Agent 变体
  skill-management/               不参与发现，不进入源 Git
    staging/                      未接受候选
    receipts/
    backups/
```

注册记录和包标记文件名只是参考设计，不是 Agent Skills 标准新增字段。完整包的隐藏快照用于保留整体身份，避免把嵌入的每个 Skill 都暴露为无命名空间的顶层命令。普通独立 Skill 则直接放在一级子目录，保留完整资源。

安装环境、依赖缓存、凭证、收据和备份不进入源 Git。必要的兼容视图可以链接已核验的独立运行环境，但不把它当成 Skill 源码。项目的 MIT 许可证也不会替第三方或专有 Skill 重新授权。

## 来源身份与版本选择

分别记录上游来源及固定 ref、Skill 声明版本、插件或市场版本、安装溯源、可复现内容摘要和已接受源身份。它们回答不同问题，不能用最大的数字或最新修改时间替代其他证据。

比较完整发布单元，包括正文、脚本、references、assets、清单、许可证、入口语法及工具要求。内容摘要应计入执行权限和链接目标，并公开算法与排除项。摘要用于发现漂移，不等于发布者签名，也不代表获准执行代码。

同名入口要区分内容相同、宿主语法生成差异、语义差异和运行时耦合。尚未确认的语义或权限差异阻止自动替换。已经接受的适配放在同一共享包或确定性入口生成器中，不产生独立可编辑副本；上游身份与适配版本仍分开记录。

完整插件或工作流套件作为一个版本单元。子技能和公开别名是父包拥有的导出入口，不能沿别名单独更新。保留包内相对引用及原生命令命名空间。

## 获取、发布与更新流程

以下是规划操作，不是本版本已经提供的命令：

1. **盘点。** 读取正式源、真实路径、软链、原生管理策略及运行时发现结果，不按名称判断兼容。
2. **暂存。** 获取明确上游 ref 或完整本地候选，放在所有 Skill 扫描根之外，不执行 bootstrap 或原安装器。
3. **审查。** 对比完整内容、版本证据、许可证、依赖、调用变化与权限要求；风险差异交给用户决策。
4. **发布。** 再次校验已审查候选的摘要；更新同时校验当前源摘要。完整发布到中央，保留旧包和阶段收据。
5. **接入。** 只创建或调整选定客户端的受管链接或兼容视图。替换前核对原件，保留冲突和无关配置。
6. **验证。** 依次确认源码、入口、新进程原生发现，以及一次已授权的代表性调用，分别报告结果。
7. **版本准备。** 暂存正式源与受管元数据供审查；提交、推送保留各自授权边界。暂存树不等于 Git 历史。

发布不得先删除中央目标，再让软链等待替换。参考本机实现使用 macOS 的受保护目录交换；跨平台等价方式必须单独验证。包交换、注册记录和客户端配置不是一个全局原子事务，要用收据记录阶段，为共享目标指定单写入者，并对配置使用预期版本检查。

回滚只撤销收据拥有的变化，遇到后续编辑、被修改的备份或已退役链接目标时拒绝覆盖。中断或结果未知时先读回并核对，不能盲目重放，也不能拿旧的用户整份配置覆盖新修改。

## 客户端发现与兼容视图

集中存储不等于所有客户端采用同一种扫描配置。逐个确认真实 loader、当前作用域、安装版本与调用规则。

| 客户端 | 发现或接入方式 | 必须验证 |
| --- | --- | --- |
| Codex | 当前官方文档已经支持直接发现 `~/.agents/skills`。只有确有兼容需要时保留旧原生入口，并处理重复可见性。 | 同名条目可能同时出现，路径不会替用户选择正确版本。 |
| Claude Code | 官方个人目录是 `~/.claude/skills`，用实测支持的软链或加载方式接入中央源。 | frontmatter、参数、动态命令、插件命名空间及调用限制不能丢失。 |
| TRAE IDE 与 CLI | 参考本机布局共用 `~/.trae/skills`，不是跨版本的平台保证，要读取实际配置。 | 共用目录只设一个写入负责人，另一个客户端负责验证；保留原生管理器归属。 |
| TRAE CN | 参考本机布局使用 `~/.trae-cn/skills`，需要独立的运行时核验。 | 不能从 IDE 的行为推断 CN 的发现、更新和管理规则。 |
| 其他 harness，包括 DSH | 通过其受支持 Skill loader 或宿主适配入口接入。 | MCP 已连接不代表它会发现本机 Skill 文件。 |

各客户端只启用选定的共享子集，并核对所需工具和语义兼容。能力交集要比较内容与依赖，不只是显示名称。不能为隐藏一个重复导出而禁用整个插件，也不能递归暴露全部嵌入 `SKILL.md` 而不定义公开入口。

优先使用单 Skill 目录级软链。既有可执行路径要求不同结构时，可用受管视图链接正文与资源，再单独链接运行环境。所有受管路径都要登记和核验，未知文件不能被整目录覆盖。

原生插件缓存可以保留实体。当客户端要求原生安装时，用受支持生命周期从已接受的完整包生成缓存，保留命名空间、启用状态和信任状态。目标是一份可编辑真源，不是磁盘上绝无缓存副本。

## 保证后续安装仍集中

一次迁移不够：旧安装器可能重新复制原生实体、沿软链写入中央，甚至卸载时删除共享包。获取、安装、更新、重装、卸载必须经过统一源管理入口，并适配既有安装器或生成器。发布源和接入客户端仍是两项操作。

在各 Agent 的用户级规则中说明这条约束。只通过 helper 支持的目标目录选项重定向获取，并在发现范围外暂存。不要重定向整个 Agent Home，把配置、凭证和运行时一起搬走。管理器缺失或验证失败时保留候选和原件，停止发布，不静默退回客户端实体目录。

完整插件不在初版实现范围内。未来适配器须区分“绑定源码”和“刷新原生缓存”。只用预期版本检查修改准确的受管 catalog 或配置条目，不为替换单个源而删除、重装整个 marketplace。Hook、MCP、app 或 agent 契约变化单独审查。

## 信任、权限与失败边界

可选的工具前拦截器可以拒绝已识别的原安装器或受管原生路径写入，但必须由用户明确启用、信任。未阻断的输出保留现有审批流程，不能替它批准权限。固定并审查实际执行代码，变化后核验当前原生信任状态。

它是保护措施，不是操作系统隔离：不透明脚本、同用户的其他进程及安装器内部写入仍可能绕过命令识别。匹配同一事件的 Hook 可以并发启动，一条拒绝不代表另一条没看到事件或没发送 telemetry。不能用软链、自然语言规则或 Hook 宣称绝对写隔离或数据隔离。

选择冲突语义、扩大权限或网络目的地、改变原生或托管生命周期、退役不兼容包、公开受限内容前，要取得明确决策。内容检查不自动授权对外发送、生产变更、Hook 信任或权限升级。

## 验收与后续集成顺序

分别验收以下结果：

- **源码。** 一份已接受的可编辑包，完整版本证据和许可证审查，Git 不含运行时或凭证。
- **文件系统。** 链接或视图正确、内容和执行权限一致，没有独立原生源漂移，未决原件被保留。
- **生命周期。** 安装、更新、卸载可重复，拒绝漂移，回滚安全，共享写入和中断阶段可核对。
- **运行时。** 每个受支持客户端的新进程实际发现预期入口，并保留调用策略。
- **执行。** 一次最小且获授权的真实业务调用使用了预期资源和工具；加载了名称不是这项证据。

[初版可选模块](../extensions/skill-source-management/README.zh.md)已实现独立包检查、候选暂存、受保护发布、接入、撤回、收据与选择性回滚。原生隔离夹具验证 Codex 发现及 Claude 正文注入，不能据此声称生产业务执行、所有客户端或跨平台生命周期均通过验证。本机特有管理器、个人清单和私有包未迁入开源模块。

当前可选 CLI/适配器包是初版落点。后续只扩展分别验证过的客户端和文件系统策略，不导入个人盘点或硬编码安装路径。保持现有 `/v1`、`/mcp` 配置 schema 不变。DSH 管理界面、周期更新编排和更多平台适配归 P1；托管多用户分发和严格 OS 写隔离归 P2，不作为本机共享前置条件。
